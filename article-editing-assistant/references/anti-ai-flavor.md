# Anti-AI Flavor · 去AI味词表与句式黑名单

整理中文语音草稿时，**最容易在"我把它整理成文章"这一步引入AI味**。这份清单用来在成稿后自检：命中就改，宁可短一点，不要套话。

核心原则：**去AI味的本质不是"换词"，是"给具体"**。抽象、套话、升华，背后都是不知道细节而不得不模糊。语音草稿里有真实的细节、例子、第一人称判断——把它们留下来，AI味自然没处生根。

---

## 一、套话词表（命中即删或改写）

看到这些词，先问一句：**删掉它意思变了吗？没变就删。**

### 1. 开场套话（破题句）

任何内容都往上套，像在写高考作文。

- 在当今 XX 的时代 / 背景下
- 随着 XX 的不断发展
- 在科技日新月异的今天
- 众所周知 / 自古以来
- 在 XX 蓬勃发展的浪潮中
- 值得注意的是 / 值得一提的是 / 需要指出的是
- 不可否认的是 / 不难发现 / 毫无疑问
- 让我们一起来看看 / 接下来我将为你
- 深入探讨 / 具体来说 / 更重要的是

### 2. 八股连接词

- 首先 / 其次 / 再者 / 最后
- 综上所述 / 总而言之 / 总的来说
- 由此可见 / 不难看出 / 换句话说
- 一方面……另一方面……
- 在此基础上

### 3. 强调虚壳（删掉不影响信息）

- 不得不说 / 客观来讲
- 我们必须认识到
- 某种程度上 / 本质上 / 核心在于 / 关键在于
- 可以说 / 归根结底 / 不言而喻

### 4. 互联网 / 商业黑话

- 赋能 / 助力 / 抓手 / 闭环 / 沉淀
- 颗粒度 / 底层逻辑 / 顶层设计
- 链路 / 触达 / 透传 / 拉通 / 对齐
- 痛点 / 场景化 / 降本增效
- 护城河 / 破圈 / 躬身入局

### 5. 程度副词 / 虚词泛滥

- 非常 / 十分 / 极其 / 真的 / 其实
- 一种 / 某种 / 一定程度上

### 6. 名词化动词搭子（"进行+N"结构）

把动词名词化，显得正式，实则啰嗦。

| AI味 | 人话 |
|---|---|
| 进行优化 | 优化 |
| 做出选择 | 选 |
| 实现增长 | 涨了 |
| 采取行动 | 动手 |
| 加以改进 | 改进 |
| 起到作用 | 有用 |

### 7. 元评论（叙述自己在写什么）

- 让我们来探讨 / 接下来我将
- 在本文中 / 以下是几点
- 下面我将从几个方面分析

### 8. 鸡汤收尾 / 价值拔高

- 愿你 / 未来可期 / 让我们一起
- 唯有 XX，方能 XX
- 这，就是 XX 的力量
- 在未来的某一天

### 9. 排比强化型句尾

- 是 A，是 B，更是 C
- 不仅是……还是……更是……
- 既要……又要……还要……

### 10. 假亲切称呼

- 朋友们 / 家人们 / 宝子们
- 亲爱的读者 / 各位老铁

### 11. 价值判断饱和词（同段堆叠即AI味）

- 重要 / 关键 / 核心 / 显著
- 巨大 / 深远 / 卓越 / 极致
- 前所未有 / 史无前例 / 毋庸置疑

### 12. 被AI用烂的比喻

- 双刃剑 / 桥梁 / 灯塔 / 引擎
- 基石 / 催化剂 / 镜子 / 马拉松
- 钥匙 / 天花板

### 13. 四字成语滥用

同一段不超过 1 个。常见雷区：博大精深、源远流长、日新月异、砥砺前行、笃行不怠。

## 二、句式反模式（结构层的AI味）

词汇是表层，句式是深层。把禁用词全换掉，骨架不变还是一眼能认出。

### 1. 三件套排比（最强中文AI指纹）

把一个意思用三个相同结构说三遍。

- ❌ "A 是 X，B 是 Y，C 更是 Z"
- ❌ "既要……又要……还要……"
- ✅ 留最强的一个，其余删掉

### 2. 二元对立 / 否定先行

- ❌ "这不是技术问题，而是管理问题"
- ❌ "真正的 X 不是……而是……"
- ✅ 直接说事实判断："管理流程比代码本身更容易出问题"

### 3. 名词化 + 抽象搭子

见上文表格。把"进行优化/实现增长"还原成动词。

### 4. 长定语"的"字串

名词前"的"超过 2 层要拆。

- ❌ "一种基于大语言模型的、面向复杂任务的、可扩展的框架"
- ✅ "这个框架基于大语言模型，能处理复杂任务，还能扩展"

### 5. 抽象主语

让"时代 / 科技 / AI / 行业 / 未来"做事，没有具体的人。

- ❌ "时代呼唤创新" / "AI 赋能教育"
- ✅ 换成具体人或数字："去年三个团队用了这套方法，平均省了一半时间"

### 6. 立flag式金句收尾

- ❌ "这就是 XX 的力量" / "唯有坚持，方能胜利"
- ✅ 留一个具体观察，不要拔高

### 7. 总分总八股

不要默认"总—分—总"。替代骨架：直接开干 / 故事线 / 倒三角 / 单点深挖。

### 8. 节奏单调 / 句长趋同

连续 5 句字数在 ±5 字以内，读起来没有呼吸感——这是统计层的AI信号。人类写作句长标准差大（约 4.7+），AI 偏小（约 1.2）。**长短句应交替**。

### 9. 远距离叙述者

全文"人们 / 大家 / 用户"飘着，没有"我"。语音草稿本来就有强烈的"我"，整理时别把它磨掉。

### 10. 戏剧化碎句

- ❌ "三年。两个人。一个想法。"
- ✅ 这种节奏偶尔用一次有效，连用就是AI模仿"克制感"

## 三、误报防护（cluster原则）

**单点信号不动，成簇才改。** 这是防止把作者真实风格误判为AI味磨平的关键。

- 单根破折号、单个排比、一句"我觉得"——都不算AI味
- 破折号 + 三件套 + "综上所述" + 价值拔高收尾——成簇出现才是铁证
- 作者真实的口语化、短句、第一人称判断，是人类信号，**必须保留**：
  - 具体且难伪造的细节（人名、数字、场景）
  - 矛盾与未解决的张力
  - 带年代感的梗
  - 真实的括号补充或自我纠正

## 四、场景边界（避免误伤）

这些规则在以下场景要降级，只抓"删虚词 / 去名词化 / 人当主语 / 给具体"四条：

- **学术写作**：被动语态、抽象主语、长句是常态，不是AI味。只删虚词、还原名词化、加具体数字
- **正式公文**：总分总、首先其次是结构要求，不要硬拆
- **法律 / 合同**：精确性优先，不要追求口语化

## 四-bis、待确认标记法（不猜不编）

语音转写常有不清晰的地方：数字听不清、人名含糊、时间不确定、术语可能写错。遇到这些，**显式标记，不要猜，不要糊弄过去**。

统一格式：

- `【待确认：这里的人名听起来像 XX，需核对】`
- `【待确认：数字可能是 30% 或 13%，听不清】`
- `【待确认：不确定是 2023 年还是 2024 年】`

规则：
- 听不清但能猜个大概 → 标 `【待确认：可能是 X】`，保留猜测但不写死
- 完全听不清的关键信息 → 标 `【待确认：……】`，不要编一个填上
- 非关键信息听不清 → 直接删掉，不必标（比如某个无足轻重的语气词或例子）
- 用户提到的数字/人名/时间 → 宁可标待确认，也不要"听起来像"就当真

这个标记和"不编造事实"配套：编造是往文章里塞不存在的东西，待确认是承认信息缺失而不掩盖。两者都为了保真。

## 五、自检清单（成稿后过一遍）

- [ ] 开场有没有"在当今/随着/众所周知"？删
- [ ] 有没有"首先/其次/综上"？删或换自然过渡
- [ ] 有没有"值得注意的是/不得不说/本质上"？删
- [ ] 有没有三件套排比？留一个
- [ ] 有没有名词化（进行/实现/做出+N）？还原成动词
- [ ] 抽象主语（时代/AI/行业在做事）？换具体人或数字
- [ ] 有没有金句收尾/价值拔高？换成具体观察
- [ ] 句长是不是太均匀？插一两个短句
- [ ] 全文有没有"我"？没有就是AI味，把用户的第一人称加回来
- [ ] 有没有听不清的关键信息被编造或糊弄？该标 `【待确认：…】` 的标了没
