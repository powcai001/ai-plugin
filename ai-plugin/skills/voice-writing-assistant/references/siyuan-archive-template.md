# 思源入库规则

语音写作助手整理出的材料，用户同意后写入思源：

```text
归档资料/资料/素材库/{子文档}
归档资料/资料/案例库/{子文档}
归档资料/资料/文献库/{子文档}
归档资料/资料/数据库/{子文档}
```

## 分类

### 素材库

放：

- 灵感。
- 观点。
- 表达素材。
- 类比。
- 比喻。
- 可用标题。
- 金句草稿。

标题建议：`素材：{主题}`

### 案例库

放：

- 商业案例。
- 历史事件。
- 名人故事。
- 企业实践。
- 身边人的真实场景。

标题建议：`案例：{对象}-{能说明什么}`

### 文献库

放：

- 论文。
- 官方报告。
- 研究机构。
- 作者。
- 书籍。
- 需要后续阅读的链接。

标题建议：`文献：{作者/机构}-{主题}`

### 数据库

放：

- 数据。
- 统计。
- 指标。
- 年份。
- 来源。
- 表格化事实。

标题建议：`数据：{指标}-{年份或来源}`

## 入库流程

1. 先在回答末尾列出「建议入库清单」。
2. 询问用户是否入库。
3. 用户同意后，使用 `siyuan-note` skill 写入对应路径。
4. 如果路径不存在，创建子文档。
5. 如果写入失败，报告失败，并把 Markdown 内容保留在当前回答里。

## 注意

- 不要默认自动入库。
- 不要把未核实材料和已核实事实混在一起。
- 每条材料要写清「可用于说明什么」。
- 宁可少入库，也不要把低价值碎片全塞进去。
